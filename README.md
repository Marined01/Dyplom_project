# Застосунок для обліку ключів від аудиторій навчального закладу

Вебзастосунок на **Django** для обліку фізичних ключів від навчальних аудиторій: запити на видачу та повернення, передача між користувачами, групи доступу, журнал дій та аналітика для адміністратора.

**Стек:** Python 3.12, Django, PostgreSQL 16.

## Перевірка застосунку

Інструкція для **ручного тестування** основних можливостей.

### Запуск

Рекомендовано через Docker — покроково в **[DOCKER.md](DOCKER.md)**.

Сайт: [http://127.0.0.1:8000](http://127.0.0.1:8000)

### Два браузери

Цей застосунок потребує **двох ролей одночасно** (користувач і адміністратор):

| Вікно | Роль | Як увійти |
|-------|------|-----------|
| **Браузер 1** | Адміністратор | `/login/` — `ADMIN_EMAIL` з `.env` |
| **Браузер 2** | Звичайний користувач | `/registration/` — новий акаунт |

**Як не змішати сеанси:**

- два різні браузери (Chrome і Edge), **або**
- звичайне вікно + **режим інкoгніто / приватне вікно**.

В одному браузері входите як адміністратор, в іншому - як звичайний користувач 
### Приклад `.env` для перевірки

Згенеруйте `SECRET_KEY`:

```bash
python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

Приклад (підставте свій `SECRET_KEY`; паролі — **лише для демо**):

```env
POSTGRES_DB=coursework_db
POSTGRES_USER=coursework
POSTGRES_PASSWORD=demo_db_pass

SECRET_KEY=вставте-згенерований-ключ-сюди
DEBUG=True
ALLOWED_HOSTS=localhost,127.0.0.1,0.0.0.0

ADMIN_EMAIL=admin@uni.ua
ADMIN_PASSWORD=Admin12345
ADMIN_NAME=Admin
ADMIN_SURNAME=User

SEED_AUDITORIES=101,102,103,201
```

Після `docker compose up` автоматично створяться адмін і вільні аудиторії з цього списку.

### Сценарій перевірки (покроково)

#### 1. Адмін — перше вікно

1. [http://127.0.0.1:8000/login/](http://127.0.0.1:8000/login/)
2. Email: `admin@uni.ua`, пароль: `Admin12345` (як у `.env` вище)
3. У меню мають бути розділи для адміна (запити, користувачі, групи тощо)

#### 2. Користувач — друге вікно

1. [http://127.0.0.1:8000/registration/](http://127.0.0.1:8000/registration/)
2. Зареєструйте студента, наприклад:
   - email: `student@uni.ua`
   - ім’я / прізвище: `Тест` / `Студент`
   - пароль: ≥ 8 символів
3. Увійдіть під цим акаунтом
4. **«Вільні аудиторії»** без доступних ключів — очікувано, доступу ще немає

#### 3. Адмін — група доступу

У **першому** вікні:

1. [http://127.0.0.1:8000/groups/](http://127.0.0.1:8000/groups/) → **Нова група**
2. Назва, наприклад: `Лабораторії`
3. Відмітьте аудиторії `101`, `102`, `103` і користувача `student@uni.ua`
4. Збережіть

#### 4. Користувач — запит на ключ

У **другому** вікні:

1. [http://127.0.0.1:8000/free-keys/](http://127.0.0.1:8000/free-keys/) — з’являться доступні вільні аудиторії
2. **Подати запит на ключ** для аудиторії `101`
3. На [http://127.0.0.1:8000/keys/](http://127.0.0.1:8000/keys/) статус — «Очікує»

#### 5. Адмін — підтвердження видачі

У **першому** вікні:

1. [http://127.0.0.1:8000/requests/](http://127.0.0.1:8000/requests/)
2. **Підтвердити** запит на видачу
3. На `/keys/` аудиторія `101` — «Зайнята», тримач — студент

#### 6. Користувач — повернення

У **другому** вікні:

1. Головна `/` — ключ на руках → **Запит на повернення**
2. Адмін на `/requests/` → **Підтвердити** повернення
3. Аудиторія знову «Вільна»

#### 7. Передача ключа

1. Користувач A тримає ключ; B має доступ до тієї ж аудиторії (група або `/users/`)
2. A: **Передати ключ** → ім’я та прізвище B
3. B: [http://127.0.0.1:8000/transfers/](http://127.0.0.1:8000/transfers/) → **Підтвердити**

#### 8. Журнал і аналітика

Адмін: `/dashboard/`, `/action_view/` — статистика та підтверджені дії.

### Зупинка

- `Ctrl+C` у терміналі або Docker Desktop → **Stop**
- Повний скидання БД: `docker compose down -v`

## Локальний запуск

Потрібні: **Python 3.12+**, **PostgreSQL 16+**.

```bash
cp .env.example .env
# DB_HOST=localhost у .env

# PostgreSQL:
# CREATE USER coursework WITH PASSWORD '...';
# CREATE DATABASE coursework_db OWNER coursework;

python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Bootstrap без Docker (якщо задані `ADMIN_*` і `SEED_AUDITORIES` у `.env`):

```bash
python manage.py ensure_admin
python manage.py seed_auditories
```

Перевірка — так само [два браузери](#два-браузери) і [сценарій](#сценарій-перевірки-покроково).

## Обмеження доступу

| Хто                                            | Що бачить / може робити                    |
|------------------------------------------------|--------------------------------------------|
| **Новий користувач, який не належить до групи** | Немає доступу до нових ключів              |
| **Користувач який належить до групи**   | Аудиторії з групи                          |
| **Персональні винятки**                        | Додаткові аудиторії на `/users/`           |
| **Адміністратор (`is_staff`)**                 | Повний доступ                              |
| **`/keys/`**                                   | Усі аудиторії; **дії** — лише де є доступ  |
| **`/free-keys/`**                              | Лише вільні ключі з доступних аудиторій    |
| **Передача**                                   | Отримувач повинен мати доступ до аудиторії |

## Змінні середовища (`.env`)

Файл `.env` — у корені проєкту, **не комітиться** в git. Шаблон: `.env.example`.

### Крок 1. Створити файл

```bash
cp .env.example .env
```

### Крок 2. `SECRET_KEY`

```bash
python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

Вставити в `.env`: `SECRET_KEY=...` (без лапок).

### Крок 3. Решта полів

```env
POSTGRES_DB=coursework_db
POSTGRES_USER=coursework
POSTGRES_PASSWORD=your-password-here
DB_HOST=localhost
DB_PORT=5432
DEBUG=True
ALLOWED_HOSTS=localhost,127.0.0.1,0.0.0.0
```

Для швидкої перевірки з адміном і аудиторіями — [приклад `.env`](#приклад-env-для-перевірки).

### Довідка по змінних

| Змінна | Обов’язково | Опис |
|--------|------------|------|
| `SECRET_KEY` | **Так** | Секрет Django |
| `POSTGRES_*`, `DB_HOST`, `DB_PORT` | Так | PostgreSQL |
| `DEBUG`, `ALLOWED_HOSTS` | Ні | Режим розробки |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | Ні | Автостворення адміна (Docker entrypoint) |
| `ADMIN_NAME`, `ADMIN_SURNAME` | Ні | Ім’я адміна |
| `SEED_AUDITORIES` | Ні | Номери аудиторій через кому |
