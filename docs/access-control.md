# Обмеження доступу

Реалізація: `coursework/access.py`, моделі `User`, `AccessGroup`.

---

## Два рівні

1. **Роль** — поле `User.is_staff` (звичайний користувач / адміністратор).
2. **Доступ до аудиторій** — групи та персональні винятки.

---

## Правила

| Хто | Що бачить / може робити |
|-----|-------------------------|
| Новий користувач без груп | Немає доступу до нових ключів |
| Користувач у групі | Аудиторії, прив’язані до групи |
| Персональний виняток | Додаткові аудиторії (адмін на `/users/<id>/edit/`) |
| Адміністратор (`is_staff`) | Повний доступ до всіх розділів |
| `/keys/` | Усі аудиторії в таблиці; **дії** — лише де є доступ або ключ уже виданий вам |
| `/free-keys/` | Лише **вільні** ключі з доступних аудиторій |
| Передача ключа | Отримувач також повинен мати доступ до цієї аудиторії |

---

## Default deny

Після реєстрації користувач **не** має доступу до аудиторій, доки адміністратор не додасть його до групи або не призначить виняток.

---

## Функції перевірки (`access.py`)

| Функція | Призначення |
|---------|-------------|
| `user_has_any_access(user)` | Чи є взагалі якийсь доступ (групи, винятки або staff) |
| `user_can_access_key(user, key)` | Чи може працювати з конкретним ключем |
| `keys_queryset_for_user(user)` | QuerySet ключів, доступних користувачу |

Перевірки застосовуються при видачі, передачі та на сторінках `/free-keys/`, `/keys/`.
